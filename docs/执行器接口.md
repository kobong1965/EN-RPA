# 本地执行接口

本软件只负责运行已注册任务和返回结果，不包含大模型、任务规划或网页接口抓取。

## 文件与兼容

原有 OculiX 脚本运行器保持不变。任务库可导入 `.sikuli` 文件夹和 `.py`、`.js`、`.rb`、`.robot` 脚本；具体语言仍依赖原执行引擎的支持和环境。移除任务只移除注册，不删除源文件。

任务清单保存在软件工作区下 `执行数据/任务.json`。每次执行独立保存至 `执行数据/运行记录/<运行编号>/`：

- `运行.json`：状态、耗时、中文摘要及结构化结果。
- `结果.txt`：便于复制的结果文本（成功且结果可读时）。
- `原始结果.json` 或 `原始结果.txt`：任务返回的原文件副本。
- `执行日志.txt`：原始诊断信息，保留实际错误，不在主界面显示代码。
- 本次截图副本：仅在任务明确报告证据路径且图片属于本次执行时保存。

任务执行采用独立进程，停止时终止其子进程树。失败和取消的当前执行不会显示上一轮的结果。新结果默认未人工核对；历史生意参谋结果仅在存在 `核对结果.json` 且状态为 `VERIFIED` 时显示已核对。

所有导入任务默认最长执行时间为 10 分钟，无新输出 30 秒时显示等待提示。无输出提示不代表任务失败，也不会单独终止任务；达到最长执行时间才会停止进程并保存失败记录。任务设置中的 `timeoutMs`、`silenceWarningMs` 以毫秒计，可配置为 1 秒至 24 小时。通过执行器的 `configureTimeouts(taskId, timeoutMs, silenceWarningMs)` 保存；修改只影响下一次运行。图形界面从“任务库 → 执行设置”调整，对用户分别显示分钟和秒。

生意参谋的目标账号通过 `String sycmAccount()` 读取，通过 `configureSycmAccount(String)` 修改，保存在工作区 `oculix-flow/千牛启动.properties` 的 `targetAccount` 属性中。配置使用 UTF-8，修改账号时保留 `shortcut`、`windowTitle` 及其他现有属性。缺少属性时使用此安装的明确默认账号 `示例账号:店铺`，不会自动选择任意店铺。输入须为千牛顶部已登录标签的完整名称；去除首尾空格后最多 128 字符，不能留空、包含换行或控制字符，运行中禁止修改。

此配置选择已有登录会话，不接收账号密码。图形界面入口为“任务库 → 生意参谋关键词 → 执行设置”；目标账号未登录时，应先由用户在千牛中完成登录。

执行器在后台每秒更新并保存心跳。`phase` 为 `starting`、`running`、`stopping` 或 `finished`（未运行时为 `idle`）；`heartbeatAt` 为最近心跳时间，`lastOutputAt` 为最近收到输出的时间，`durationMs` 为已用时，`silentForMs` 为无新输出时长，`stalled` 表示达到提示时长，`healthMessage` 为可直接显示的中文说明。`pid` 在子进程创建完成后提供。超时使用 `status: failed` 和 `failureCode: TIMEOUT`，用户主动停止使用 `status: cancelled`。

## 让任务返回结果

任务可输出中文进度和明确错误，所有语言共用此协议，每条单独占一行：

```text
OCULIX_PROGRESS 正在读取当前页面的数据
OCULIX_ERROR 未找到目标入口，请检查页面状态或图片模板。
```

中文进度会更新界面阶段。`OCULIX_ERROR` 的明确原因优先于包装器随后输出的通用错误和调用栈；错误原文仍保存在 `rootCause` 和原始日志中。没有使用协议的旧任务也有启动状态、心跳、无输出提示与超时控制。

### 明确报告完整流程的步骤

生意参谋任务的业务步骤包含打开千牛、进入工作台、打开生意参谋、进入市场、打开搜索排行、读取关键词、保存结果。引擎准备独立显示为 `phase: starting`，此时业务步骤全部为 `pending`，不表示任何业务操作已经完成。

任务可以用严格行首的结构化步骤事件报告开始和完成，每条 JSON 单独占一行：

```text
OCULIX_STEP {"id":"open-qianniu","status":"running","message":"正在启动千牛"}
OCULIX_STEP {"id":"open-qianniu","status":"done","message":"千牛窗口已确认"}
OCULIX_STEP {"id":"enter-workbench","status":"running","message":"正在进入工作台"}
```

| id | 显示名称 |
|---|---|
| `open-qianniu` | 打开千牛 |
| `enter-workbench` | 进入工作台 |
| `open-sycm` | 打开生意参谋 |
| `enter-market` | 进入市场 |
| `open-ranking` | 打开搜索排行 |
| `read-keywords` | 读取关键词 |
| `save-results` | 保存结果 |

`status` 支持 `running`、`done`、`failed`；应确认对应页面或操作完成后再报告 `done`。`id` 也可以用 `name` 或 `step` 字段中的完整中文步骤名称代替。`message` 可省略，提供时应为不超过 180 字符的中文说明。无效或不认识的可选步骤事件会留在日志中，不会推进步骤。

收到有效的 `OCULIX_STEP` 后，本次 `stepProtocol` 为 `structured`，后续 `OCULIX_PROGRESS` 只更新说明，不覆盖结构化步骤状态。`activeStepId` 指向正在执行的步骤，没有活动业务步骤时为空。脚本明确报告某步 `failed`，本次执行不会因为进程返回 0 而伪装成功。

旧生意参谋任务仍可使用普通中文进度；只会推进实际报告过的步骤，不会把跳过或未报告的“打开千牛”“进入工作台”补成已完成。成功记录中仍为 `pending` 的旧步骤应显示为“未报告”。执行器自行报告最后的保存结果阶段。

图形界面可以通过 `taskSteps(taskId)` 获取未运行时的步骤蓝图（全部 `pending`），运行或查看记录时读取对应 `steps` 数组。每项包括 `id`、`name`、`status`。普通新导入任务保持准备执行、执行任务、读取结果、保存结果四个通用阶段，对应 `prepare`、`execute`、`read-result`、`save-results`。

在任务标准输出中单独输出一行，路径使用绝对路径：

```text
OCULIX_RESULT E:/任务输出/本次结果.json
```

支持以下 JSON 格式：

```json
{"rows":[{"关键词":"长裤","排名":1},{"关键词":"工装裤","排名":2}]}
```

也支持根数组、`data` / `list` 数组，以及 UTF-8 文本文件。生意参谋原有的 `OCR_CANDIDATES <路径>` 输出协议保持兼容。每次任务应生成独立输出文件，避免多个任务覆写同一文件。

如果任务正常退出但没有返回结果文件，软件会说明“执行完成，任务未提供结构化结果”，不会伪造业务数据。

任务可在创建本次专用输出目录后报告证据目录，便于执行失败时仍关联截图：

```text
OCULIX_RUN_DIR E:/任务输出/本次运行目录
```

也兼容带时间前缀的 `RUN_DIR <绝对路径>`、`CAPTURED <截图绝对路径>`。只使用当前子进程输出的路径线索，不从历史目录猜测；只关联本次开始后写入的图片。成功结果优先使用关键词截图，失败优先使用名称包含 `failure` 的截图，保留原始来源并尝试复制到本次结果目录。

## 其他软件下达指令

本机接口默认关闭，每次启动软件后需要在设置页开启。仅监听 `127.0.0.1`，默认端口 `18986`。设置页提供连接信息复制功能。身份令牌保存在本地 `执行数据/连接.json`，请只交给获准控制本机的软件。

所有请求必须带请求头：

```text
Authorization: Bearer <本机令牌>
```

接口不提供跨域授权，并拒绝带 `Origin` 的浏览器请求。只允许执行已经注册到任务库的任务，不接收任意源代码或系统命令。

| 方法 | 地址 | 内容 |
|---|---|---|
| GET | `/api/health` | 当前运行状态 |
| GET | `/api/tasks` | 已注册任务清单 |
| GET | `/api/runs` | 运行历史及结果 |
| POST | `/api/run` | 请求体 `{"taskId":"sycm-keywords"}` |
| POST | `/api/stop` | 停止当前任务；请求体可为空 |

同一时间只执行一个任务。任务正在执行时重复下达运行命令会返回 HTTP 409。身份验证失败返回 403，指令参数错误返回 400。

主界面处于“高级工具”时暂停接受开始任务的指令，返回 HTTP 409 和“请先返回执行中心，再运行任务。”，避免与录制或原脚本运行同时控制桌面。任务、状态与历史查询仍然可用。

返回状态值：`idle` 等待、`running` 执行中、`success` 完成、`failed` 未完成、`cancelled` 已停止。`summary` 和 `stage` 为中文展示文字。`rows` 为任务本次结果，`verified` 为独立核对状态。
